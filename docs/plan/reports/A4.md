# Report — A4 Tier 3 generic extraction, classifier cascade, field offsets everywhere, robustness

- **Date / author (human + agent):** 2026-09-28, Person A (Arnav) with Claude Opus 5

## What was built

"Ultra-messy in, useful out" is real. A log from a source nobody wrote a contract for no longer
falls out as tier 4 — it arrives as **tier 3** with its IPs, users, hosts and key/values extracted,
every one of them pointing at real bytes in the original event.

The visible proof is in the goldens: `linux_sshd.log.json` now reports `tiers [1, 3]` where A3 left
it at `[1, 4]`, and every OT historian line is tier 3 with byte-correct Devanagari offsets.

**New engine modules**

| Module | What it does |
|---|---|
| `tier3.py` | The classifier cascade (`cascade`) and the tier-3 build (`build`): observables with byte offsets, `unmapped`, time from the first timestamp token that parses, severity from the word vocabulary. |
| `class_hint.py` | The keyword/field table from the phase file → `(class_uid, confidence)`, plus `severity_from_words`. The hint rides in `ulpf.class_hint`; **`class_uid` stays 0**. |
| `inflight.py` (in `veyra_common`) | The crash-loop journal: `data/state/<service>_inflight`, so a record that kills the *process* is quarantined on restart instead of looping forever. |

**Cascade order** (deterministic, recorded in `ulpf.parse_path` as `auto:<layer>`): syslog header →
JSON body → CEF → LEEF → `k=v` density ≥ 0.5 → consistent delimiter → plain text, then kv-parse
`json.__rest` — which is where the demo's `… } | trace=` shape hides half its data.

**What tier 3 refuses to do** is as much of the work as what it does. It never sets `class_uid`; it
never assigns an IP to `src_endpoint` or `dst_endpoint`, because at tier 3 nothing says which end is
which and a wrong guess makes a SIEM rule fire on the wrong host; and it never invents a byte range —
a lossy decode yields `derived_fields[path] = "token:no-span"`, not a fabricated span.

**Robustness**

| Guard | How |
|---|---|
| RE2 only | `test_robustness.py` parses every engine module's AST and fails on any `import re`. Plus a second test that at least one module really does import `re2`, so the first cannot pass vacuously. |
| Budget | `types.Budget` (`limit_us`, `started_us`) checked **at stage boundaries**, not measured afterwards. Over budget → tier 4 `budget_exceeded`, `raw_data` kept. |
| Cold start | `Engine._warm()` at construction and after `load()` compiles validators and loads timezones, so the first event is not downgraded for one-time work (it measured 14 ms before this). |
| Size | Over `VEYRA_MAX_EVENT_BYTES`, only the prefix is parsed; the full raw still travels in `raw_data` via `decode_text_only` (no offset map, which on a 200 KB event is most of the budget). |
| Exceptions | The top-level guard turns anything into tier 4 `engine_crash` with the exception class name in `reason_detail`. |
| Crash loop | `InflightJournal` + `normalizer.poison_records` — see below. |
| Fuzz | `hypothesis` over random bytes, random text, plausible log fragments, deep/broken JSON, and bit-flip/truncate/insert/duplicate mutations of the real corpus. |

**The crash-loop guard is about process death, not exceptions.** `TxnProcessor` already retried a
raising batch and quarantined it after `poison_max_retries`, but that counter lived in memory. The
failure that actually takes a pipeline down is a record that makes the process *die* — a segfault in
a C extension, the OOM killer — where the transaction aborts, the offsets never move, the container
restarts, and the same record kills us again, forever. So the attempt count is now journalled to
`data/state/normalizer_inflight` (write-temp-then-rename) before each batch and cleared after a
successful commit. A batch already attempted `VEYRA_POISON_MAX_RETRIES` times is skipped **without
being handed to the processing function at all**, since running it is the thing that kills us, and
`poison_records` emits one tier 4 `engine_crash` DLQ record per message with its Kafka coordinates —
P2 holds: skipped, never silently dropped.

## Two bugs the work found

**1. `provenance_check`'s second half found unexplained claims — in tier 1.** Once every value had to
be either located or declared computed, tier-1 observables and several defaulted fields turned out to
be claims nobody accounted for. Fixed at the source rather than in the checker:
`mapping.build_observables` now returns its sources (`observables.<name>` → `from:<path>`), and every
engine default declares itself (`default:unknown`, `default:informational`, `default:raw_prefix`,
alongside `vocab:severity_words`, `ts:token`, `received`).

**2. The fuzzer found a verifier bug no corpus line could have shown.** `provenance_check` decoded raw
slices as UTF-8, while the engine had built the offsets against whatever codec `decode()` detected. A
Big5 or GB18030 line therefore reported a provenance failure although its offsets were exact. The
verifier now reads the bytes back with `ulpf.encoding.detected`. This is the whole argument for
fuzzing: the corpus is all UTF-8, so no amount of corpus testing would have reached it.

## One consequence of masking, worth knowing before B6 and C6

The DLQ copy of an event **cannot be found by searching for the user**: `text_masked` replaces it with
`<USER_1>`, which is the entire point of masking. The integration test tripped over this — it looked
for its probe marker in the DLQ record and did not find it — and the fix is the same one a console
needs: join on `event_uid` (or `template_sig` for a cluster), never on the masked text. IPs *are* still
searchable, because A4 keeps them deliberately.

## Deviations from the phase file

1. **The cascade and the tokenizer both work on the first 4 096 characters** (`CASCADE_MAX_CHARS`).
   Peeling a 60 KB line costs ~8 ms per layer, over the whole per-event budget on its own, and such a
   line is noise past the first few KB. `raw_data` keeps every byte, so nothing is lost — only the
   parsing window is bounded. The phase file does not specify a window; it does specify the budget.
2. **The per-example fuzz timing assertion is a loose 200 ms ceiling, not 2× the budget.** A timing
   assertion inside a fuzz loop is a flake magnet on this laptop — it failed once during a concurrent
   docker build and passed alone immediately after. The 2× claim AC4 actually makes is measured on its
   own, unloaded. What the fuzz ceiling is there to catch is quadratic behaviour, and 200 ms does that.
3. **The 50 000-case run is marked `slow`.** It adds 30 s and finds nothing the ~1 500 examples on
   every `make test` do not already cover, so it is run deliberately rather than on every commit.
4. **`severity_id` 0 is declared, not left implicit.** Unknown is the engine's default, not something
   the source said, so it is recorded as `default:unknown` — otherwise `provenance_check`'s second
   half reports it as an unexplained claim, and it would be right to.

## Known issues / risks

1. **A stale container image will silently look like a tier-3 bug.** The two new integration tests
   failed on the first run with `field_offsets: {}` and tier 4 — not an engine defect, just
   `veyra-normalizer` still running the A3 image, because `make up` does not rebuild. `make build
   SERVICES="…"` needs the same `SERVICES` as `make up`, or compose reports "No services to build" and
   changes nothing. Worth remembering at CP2, when several tracks will be chasing the same symptom.
2. **The crash-loop guard is tested at the unit level, not by actually killing the process on a poison
   record.** The journal's behaviour across a simulated restart is covered (10 tests), and the
   quarantine path was already exercised by A3's `kill -9` test, but "a record that segfaults the
   interpreter is skipped on the third restart" has no end-to-end test — there is no such record to
   hand. A6 or S2 could inject one with a deliberately fatal code path.
3. **Tier 3 severity is a word match, and words lie.** A line containing "failed to disable alerting"
   scores as a failure. This is exactly the imprecision the contract loop exists to remove, and tier 3
   labels itself `unknown_template` so nothing downstream should treat it as authoritative — but the
   Wazuh rules at A6 should not escalate on tier 3 severity alone.
4. **The journal costs one small file write per batch** (a JSON write plus a rename, no fsync — a
   power cut may lose the last attempt count, which only means one extra retry). At laptop batch rates
   that is a handful of writes per second and did not move the bench, but it is per *batch*, so a
   configuration with very small batches pays it more often. If A6's throughput bench ever shows it,
   the fix is to journal only when the previous batch failed.
5. **`linux_sshd@1` still covers only 3 of the corpus shapes** (from A3). Those 13 lines are now tier 3
   with observables rather than tier 4, which is a better failure but still a gap — `REQUEST @C` stands.

## Notes for downstream phases

**A5 (shadow, backtest, replay):** tier 3 gives backtest a real "before" to compare against — an
unregistered source now produces observables and offsets, so a candidate contract's improvement is
measurable as tier 3 → tier 1 plus field coverage, not merely "tier 4 became tier 1". `Budget` is
threaded through `normalize`, so a backtest over thousands of events should pass a generous limit or
none rather than inherit the per-event one.

**A6 (router + Wazuh):** `ulpf.class_hint` is populated on tier 3 and is **a hint** — route on
`ulpf.tier` and `class_uid`, and if a rule wants the hint, keep it out of anything that pages a human.
`observables[]` names follow `ip_1`, `ip_2`, `user`, `host_1`, which is what a Wazuh decoder should key
on for an uncategorized event.

**@B (B6 highlights):** `provenance_check(event, raw_bytes)` is the highlighter's contract and it now
covers both halves — a path missing from `field_offsets` is guaranteed to be in `derived_fields`, so the
UI can always say *why* a value has no highlight instead of showing nothing. One correction that matters
for B6: decode the raw slice with `ulpf.encoding.detected`, not UTF-8, or a non-UTF-8 event will
highlight the wrong bytes.

**@C (C3 drift, C4 drafter):** tier 3 is now the real input to both. `ulpf.template.sig` is stable for
tier 3 too, so Drain3 clustering has a key; `extract_tokens` is final, and `mask()` keeps IPs on purpose
so a draft can propose `src_endpoint.ip`. `unmapped` carries every kv/JSON field the cascade found —
that is the candidate set a drafter should be choosing from.
