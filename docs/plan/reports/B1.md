## What was built

| Piece | Where | What it does |
|---|---|---|
| ClickHouse schema | `packages/veyra_lineage/migrations/00{1,2,3}_*.sql` | 10 tables and 9 materialized views: `raw_events`, `norm_lineage`, `norm_events`, `window_roots`, `vault_locations`, `segments`, `receipts`, `dlq_events`, `shadow_diffs`, `audit_log`, `search_index` (+ its two feeders), and the per-minute source/route rollups |
| Migration runner | `veyra_lineage/migrate.py` | Numbered, idempotent migrations with an applied-versions table, plus `ensure_ttl` for `VEYRA_LINEAGE_TTL_DAYS` |
| Row builders | `veyra_lineage/rows.py` | One builder per topic, mapping IF-ENVELOPE / IF-NORM-EVENT / IF-LINEAGE onto table rows, including `ulpf.field_offsets` |
| Query library | `veyra_lineage/queries.py` | `overview`, `source_health`, `search` (with `classify` picking the match kind), `event_detail`, `template_events`, run in parallel where they are independent |
| Result models | `veyra_lineage/models.py` | The typed shapes the evidence API serves as-is (IF-API-EVIDENCE) |
| Indexer service | `services/lineage_indexer/` | Consumes the topics and writes batches, flushing at `INDEX_BATCH_ROWS` or `INDEX_BATCH_MS`, with dedup on replay |
