## What was built

**`services/control_api`**: FastAPI on SQLite (SQLModel, WAL), one module per job.

| Module | What it does |
|---|---|
| `tables.py`, `db.py`, `migrations.py` | C1 tables plus placeholder C2–C4 tables; WAL and foreign keys; a forward-only migration list |
| `security.py`, `auth.py` | argon2 passwords; opaque session tokens (only `sha256(token)` stored); `Principal`, `require(*roles)`; tenant scoping (another tenant is 404, a missing role is 403) |
| `routes_tenants.py`, `routes_sources.py` | tenants, sources, API keys. The secret is returned once; only `sha256(pepper + secret)` is stored and published. |
| `publisher.py`, `messages.py` | the single publisher of the compacted `control` topic. Each mutation publishes and flushes before its SQLite commit, and a broker failure is 503 with nothing committed. `republish_all` at startup and reset. |
| `inventory.py` | IF-INVENTORY writer: `sources.csv.tmp` plus an atomic rename, and the reload stamp touched |
| `audit.py`, `routes_audit.py` | IF-AUDIT to SQLite and the `audit` topic; `GET /audit` scoped by tenant |
| `events.py`, `routes_stream.py` | SSE hub with bounded per-client queues and a 15 s heartbeat |
| `contracts_repo.py` | the registry's git history via dulwich (no `git` binary in the image), with a `seed` tag |
| `seed.py` | `python -m control_api.seed --scenario sih_main`: tenants, users, NTRO sources, library contracts |
| `routes_internal.py` | `/internal/reset`, `/internal/demo/last-key`; `/internal/drift` was a stub until C3 |

**`packages/veyra_contracts`** (C2 task 1, pulled forward because C1 AC1 publishes *compiled* contracts): Pydantic models of IF-CONTRACT-YAML, the OCSF subset catalogue, the pattern compiler (RE2), and a deterministic `compile()`.

**The contract registry** moved to its own repository beside `Veyra/` (`../contracts-repo`; see the 2026-09-28 changelog entry).

## Deviations from the phase file

1. **The compiler shipped with C1**, because C1 AC1 publishes compiled contracts. The phase file lists it as C2 task 1.
2. **dulwich instead of GitPython or the `git` CLI:** the shared Python image has no `git` binary (TC6).
3. **Knobs live in the shared `Settings`**, not a service subclass, because `test_settings_topics_service.py` rejects profile keys the base `Settings` doesn't know (TC5).
4. **The seed maps `src_fw_dmz_01` by `syslog_host fw-dmz-01`**, as C1 and B7 name it; the S0 CSV's `fw01` row is replaced on the first rewrite (TC8).
5. **SSE is a plain `StreamingResponse`** (no `sse-starlette`) (TC9).
6. **The seed reads library contracts from the registry** (`../contracts-repo/t_ntro_core/`), not `packages/veyra_engine/tests/contracts/`, which holds only the authsrv test contracts.

## Known issues / risks

1. **A publish failure doesn't purge the producer queue.** SQLite rolls back and the request gets 503, but the unacknowledged control and audit messages may still reach Kafka later. Candidate fix: `purge()` on `ProducerLike`, called in the error path.
2. **`/internal/*` is reachable through Caddy:** `handle_path /api/control/*` proxies everything. Fix in the shared Caddyfile: `respond /api/control/internal/* 404`.
3. **Inventory writes are not batched.** A1 measured that a Vector reload drops in-flight events; each source change rewrites the CSV once.
4. **An unknown listener** in the key card shows `port: null`.
5. **Fixed in C2:** until C2, `/internal/reset` left keys created since seed live on `control` (no tombstones).
