| Module | What it does |

## Deviations from the phase file

1. **Raw bytes come from Kafka at `raw_ref`, and replay progress from `lineage`**, not from B4 endpoints that don't exist yet (TC18). evidence-api is used only for sig → events.
2. **Golden files are snapshots** (the expected file is the whole normalized event, written by `--update`), as A3 did (TC19).
3. **Failing submissions are not committed to git**; only versions that pass reach the registry history (TC20).
4. **The backtest's "sample of tier 1 events"** for regression detection is deferred. It needs an evidence-api listing by source (REQUEST @B).
5. **First versions get no live shadow** (TC16).

## Known issues / risks

1. **A version whose publish fails after its git commit** leaves an orphan commit in the registry. It's harmless: the next submission of that version commits again.
2. **`seed` in the registry repository** must be moved to include the golden samples, or a demo reset deletes them. The owner does this (force-pushing the tag).
3. **Replay needs the normalizer to write `replay_job_id` on `lineage`** (A5); without it every job times out.
