- **Branch / PR:** committed directly to `main`

## What was built

The S0 stub is gone. `veyra_engine` is now the real deterministic engine, and `services/normalizer`
runs it in a transactional Kafka loop. The public surface did not change: every name S0 froze is
still there with the same signature, and `tests/test_engine_surface.py` — written against the stub —
still passes unmodified apart from three `decode` assertions.

**`veyra_engine` modules**

| Module | What it does |
|---|---|
| `decode.py` | UTF-8 strict → best-guess codec → lossy replace, **plus the char→byte offset map**. A lossy decode refuses to hand out byte spans rather than lie about them. |
| `spanjson.py` | Own recursive-descent JSON scanner that records a char span for every scalar. Strings are unescaped in the value but the span covers the raw escaped text, so a span slices to what a human sees. Trailing text becomes `json.__rest` — the demo's `… } \| trace=` shape. |
| `peel.py` | Layers `syslog` (3164 + 5424 + no-pri), `json`, `kv`, `cef`, `leef`, `csv`, `regex`, `base64`, plus `run_layers` to apply a contract's declared order with a depth cap. |
| `template.py` | Compiles IF-CONTRACT-YAML pattern syntax (`<user>`, `<ip:ip>`, `<n:int>`, `<*>`, …) into an anchored RE2 with named groups; first match wins. |
| `mapping.py` | Applies `capture \| field \| const \| vocab \| ts \| text`, types values, writes nested OCSF paths, and splits provenance: **located** values get byte offsets, everything computed gets `derived_fields`. |
| `timeparse.py` | Formats, timezone, year inference (including the December-read-in-January rollback), clock skew — reading only `envelope.received_time`, never the clock. |
| `validate.py` | Two validators against one vendored schema: `fastjsonschema` on the hot path, `jsonschema` to explain a failure. |
| `mask.py` | Secret-key values and emails masked, **IPs deliberately kept** (the drafter needs them). A4 finalizes it. |
| `testing.py` | `mini_compile` — IF-CONTRACT-YAML → IF-CONTRACT-COMPILED, standing in for C2's compiler. |
| `ocsf/` | The vendored subset schema + a README recording exactly what differs from upstream OCSF and why. |

**`services/normalizer`** consumes `^raw\..*` plus `replay.raw` through
`veyra_common.kafka.TxnProcessor`, so `norm.<category>` + `lineage` + `dlq` and the consumed offsets
commit in **one transaction**. `control.py` follows the compacted `control` topic and swaps the
contract set atomically. `ulpf.raw_ref` is filled from the real Kafka coordinates by the service —
the engine cannot know them.

**A-owned scaffolding until C lands:** `tools/mock_control_publish.py` publishes contracts, sources,
vocab and routes the way C1 will. Delete it when C1 ships.

## OCSF 1.9.0 verification

IF-OCSF-SUBSET says "verify ids against the pinned schema", so every id was checked against
`https://schema.ocsf.io/api/1.9.0/classes/<name>` rather than trusted:

| Class | uid | category_uid | Activities used | Verdict |
|---|---|---|---|---|
| Base Event | 0 | 0 | 0, 99 | matches |
| Process Activity | 1007 | 1 | 1 Launch, 2 Terminate | matches |
| Authentication | 3002 | 3 | 1 Logon, 2 Logoff | matches |
| Network Activity | 4001 | 4 | 1 Open, 2 Close, 5 Refuse, 6 Traffic | matches |
| HTTP Activity | 4002 | 4 | 1 Connect … 99 Other | matches |

`severity_id`, `status_id`, `disposition_id` and `action_id` enums match the plan exactly.
`type_uid = class_uid * 100 + activity_id` holds.

**One difference worth stating:** OCSF 1.9.0 marks `cloud` and `osint` **required** on several
classes. VEYRA is a log pre-processor and does not invent cloud metadata, so the vendored subset does
not require or validate them. Nothing downstream needs them (Wazuh matches on `veyra.*` plus the
mapped fields). Recorded as an IF-OCSF-SUBSET clarification.

## Deviations from the phase file

1. **`fastjsonschema` on the hot path.** The phase's own risk list said "jsonschema is slow — cache
   validators and **measure**". Measured: 216 µs/event, about a third of the pipeline. The same
   schema file compiled with `fastjsonschema` costs ~10 µs and catches the same defects (verified:
   bad enum, wrong type, missing required). Plain `jsonschema` is kept to produce the full error list
   when an event really is invalid, which is off the hot path by definition.
2. **Tier 3 is deliberately still tier 4.** A3's table says tier 3 is A4's work; the code path
   (`_tier3_placeholder`) is in place with the correct DLQ reason (`no_contract` /
   `no_template_match`) and the peeled fields carried in `unmapped`, so nothing is lost meanwhile.
3. **Goldens are snapshots, not hand-written expected files.** `tests/expected/*.json` records tier,
   class, activity, every mapped path **with the bytes its offset points at**, time provenance and
   DLQ reason per corpus line, regenerated with `--update`. Hand-maintaining 88 expected JSON
   documents would have rotted immediately.
4. **`linux_sshd@1` does not cover the whole sshd corpus.** The seeded library contract has three
   templates; 13 of 24 corpus lines (pam_unix, publickey, disconnects, sudo, "maximum attempts") do
   not match and land in the DLQ as `no_template_match`. That is correct behaviour and exactly what
   C3's drift detection exists to surface — `contracts-repo/` is C's directory, so A did not extend
   it. Logged as a `REQUEST @C`.
5. **`authsrv` test contracts live in `packages/veyra_engine/tests/contracts/`**, not in
   `contracts-repo/`, because in the demo that contract is created live in Beat 2. `authsrv_v2.yaml`
   is the drift-loop outcome and is what A5's backtest will use as the candidate.

## Known issues / risks

1. **Peel is now the largest stage** (~190 µs of ~350 µs p50 for CEF) after validation dropped to
   ~10 µs. If A6's throughput bench needs more, that is where to look — the `kv` scan over CEF
   extensions is the hot loop.
2. **Bench numbers move with machine load.** Before the validator change, the same CEF workload
   measured 1480 → 2296 EPS depending on what else was running. The reported numbers were taken with
   the full stack up and idle; A6's bench should state its conditions the same way.
3. **`mini_compile` is A-owned and must not outlive C2.** Two compilers for one YAML dialect is a
   drift risk; the golden contracts are the shared check when C2's compiler arrives.
4. **The `base64` peel layer gives inner fields no span**, by design (they are not in the raw bytes),
   so anything mapped from inside a base64 blob is `derived`. Worth knowing before a contract maps
   through one.
5. **A contract whose template regex is broken loads with the rest working** and the failure is
   reported in `engine.load_errors`; nothing surfaces that to an operator yet. C2's lifecycle should
   refuse to publish such a version.

## Notes for downstream phases

**A4 (tier 3, offsets, robustness):** the hole is marked — `Engine._tier3_placeholder` is where the
generic extractor goes, and it already receives the peeled fields and the right DLQ reason. The
classifier cascade has its detectors ready in `peel.py` (`detect_syslog`, `detect_kv`, `detect_cef`,
`detect_leef`, `detect_csv`), so the cascade is a matter of ordering them. `decode.Decoded.byte_span`
returns `None` for a lossy decode — tier 3 must treat that as "derived", not as an error.
`provenance_check` currently checks located values; add the "every mapped path is located or derived"
half. The RE2-only rule already holds: no engine module imports `re`, because `template_sig` lives in
`veyra_common.hashing`.

**A5 (shadow, backtest, replay):** `Engine.set_candidate` keys candidates by **contract id** and
`_resolve_contract` handles the source→contract→candidate hop, including a candidate that declares a
source no active contract covers. `backtest()` exists with the real shape and needs the
`field_coverage` and richer `examples` A5 specifies. The normalizer already carries `replay.revision`
and `supersedes` through from the `replay` block, so A5's work is the semantics, not the plumbing.
`packages/veyra_engine/tests/contracts/authsrv_v2.yaml` is the candidate to test against, and
`test_authsrv_v2_upgrades_t3_to_tier_one` already proves 8/8 T3 events upgrade.

**A6 (router):** events on `norm.<category>` carry `ulpf` complete, so the router's `veyra.*`
convenience fields come straight from it (`ulpf.tier`, `ulpf.contract`, `ulpf.revision`). `lineage`
rows carry `search_terms` (observables plus user/IP/hostname) for the console's search. Receipts key
on `event_uid`, which is also the `norm.*` key.

**@B:** `norm.*` and `lineage` are live now, so B1's indexer can be built against real records rather
than `fake_norm.py`. `ulpf.raw_ref` is the real `(topic, partition, offset)` — that is the join key
back to the vault. `ulpf.field_offsets` are byte offsets into the **decoded raw bytes**, which is what
B6's highlighter needs; `provenance_check(event, raw_bytes)` is exported for exactly that.

**@C:** `tools/mock_control_publish.py` shows the exact `control` message shapes the normalizer
consumes — copy its payloads in C1 and delete the tool. `mini_compile` in
`veyra_engine.testing` is the dialect C2's compiler must match; the golden contracts and
`tests/expected/*.json` are the shared regression check. Also see the `REQUEST @C` about
`linux_sshd@1`'s coverage.
