# Report — A2 Ingest gateway: HEC-compatible push, per-source API keys, quotas, batch

- **Date / author (human + agent):** 2026-09-28, Person A (Arnav) with Claude Opus 5
- **Branch / PR:** committed directly to `main`
- **Contracts version at start → end:** v1.3 → **v1.4** (additive: IF-ENVELOPE gains optional `hec_meta`)

## What was built

`services/ingest_gateway/` is a real service now. Any shipper that can talk to a Splunk HEC endpoint
can point at `:8088`, authenticate with the key issued during onboarding, and land stamped envelopes
on `raw.<vendor>` — which is the whole "your org gets an API doc and a key" promise in Beat 2, and the
path the Maha Power auth server uses in Beat 3.

| Module | What it does |
|---|---|
| `app.py` | The three endpoints plus HEC-shaped errors. One status code per failure mode: 401 auth, 413 body cap, 400 malformed, 429 quota, 503 not-durable. |
| `hec.py` | The HEC body format, including concatenated objects with no separator. |
| `registry.py` | API keys and source records from `control`; digest lookup, `hmac.compare_digest`. |
| `quota.py` | A token bucket per source, one second of burst. |
| `producer.py` | Produce, flush with a timeout, and refuse to acknowledge anything Kafka did not accept. |
| `pepper.py` | The shared pepper file, with "not yet" and "cannot read it" told apart. |
| `settings.py` | `GatewaySettings`; the three A2 knobs already existed in `Settings` and `profiles/*.env`. |
| `API.md` | The curl documentation C1 embeds in the key card, including a ready-made Vector sink config. |

**Nothing about the envelope was reinvented.** `veyra_common.envelope.stamp` and
`veyra_common.framing.split_lines` are the functions A1's Vector config is locked against, so the HTTP
path shares the continuation rule by construction. `tests/test_parity.py` pushes S0's own parity
vectors through the HTTP endpoints and compares `raw_b64`, `raw_sha256` and `raw_len` — a verifier
re-hashing the archive cannot tell which path an event took, which is the point.

**C1's half was already there and was used as-is:** `sha256(pepper + secret)`, the pepper at
`data/keys/api_pepper`, and a revocation that **republishes the key with `status="revoked"`** instead of
tombstoning it. That last detail is what makes AC2 a matter of following the topic rather than of
polling an API.

## One piece of shared code moved

The `control` follower is now `veyra_common.control.ControlReader`. The gateway is the third consumer
of that topic and A6's router will be the fourth, and the part that must exist in exactly one copy is
the readiness rule A3 paid for: wait until every assigned partition reaches the high watermark seen at
startup, because a poll returning nothing usually means "not assigned yet", not "the topic is empty".
`normalizer/control.py` keeps only its engine-specific state and `_apply`. **A3's eight control tests
pass unmodified** — that was the acceptance condition for calling this a move rather than a rewrite.

## Decisions worth writing down

1. **A request arriving before the control backlog is read gets 503, not 401.** The gateway does not
   yet know whether the key is good, and a shipper that treats 401 as fatal would stop retrying a
   perfectly valid key. This is the difference between "the demo recovers from a restart" and "the
   demo needs the client restarted too".
2. **A key whose source record has not arrived yet is accepted**, with `vendor`/`zone` defaulted and a
   warning logged. Onboarding issues the key before the source row is published; refusing the event
   would break P2 for a configuration that is merely a few hundred milliseconds young.
3. **Quotas cost events, not requests**, and a request that does not fit is refused **whole** — a
   request is never partially accepted. A request larger than the whole bucket (a 40-line batch at
   5 EPS) is allowed once the bucket is full and drains it, or it could never be sent at all.
4. **`hec_meta` is kept beside the envelope, never merged into it.** A client's own `time` must not
   become the event time, or a misconfigured sender could rewrite history. It rides in `unmapped.hec_meta`
   and nothing maps from it.
5. **Both Stretch items were deliberately skipped.** Signed batch manifests need somewhere to register
   a source's public key, which is IF-CONTROL and therefore C's to add; nothing in the demo script
   sends OTLP.

## Two things the tests caught

**Float arithmetic in the token bucket.** Refill is `elapsed * rate`, and 0.4 s at 5 EPS computes to
1.9999999999998863 — so an exact comparison 429s a source that is sending *exactly* its quota, which
is the most common case there is. `EPSILON = 1e-9` is now a named constant with that number in the
comment.

**Masked DLQ text is not searchable** (carried over from A4 and re-confirmed here): the integration
tests match envelopes by their raw bytes, not by the DLQ copy, because `text_masked` replaces the
user. Console joins go through `event_uid`.

## Deviations from the phase file

1. **No `hec_meta` → `unmapped` mapping inside the gateway.** The phase file says the HEC `time`
   "goes to `unmapped` via the envelope `hec_meta`"; the gateway sets the envelope field and the
   **engine** does the `unmapped` fold, in one place for all four tiers, so a tier-4 event shows what
   the shipper claimed too.
2. **`POST /services/collector` is accepted as an alias for `/services/collector/event`.** Splunk
   treats them as the same endpoint and several clients post to the bare path; refusing it would look
   like a VEYRA bug to a correctly configured shipper.
3. **A `token` query parameter is accepted** in addition to the `Authorization` header, for the same
   reason: some HEC clients only support the URL form.
4. **Integration tests publish their own `apikey:` messages** straight to `control` rather than going
   through control-api's HTTP API. The message shape is C1's (`ApiKeyMessage`), and it keeps A's tests
   independent of C1 being up — `tools/mock_control_publish.py --api-key --quota N --revoke-key ID`
   covers the manual path.

## Known issues / risks

1. **A stale image looks exactly like a gateway bug** (same trap as A4): `make up` does not rebuild,
   and `make build` needs the same `SERVICES=` or it reports "No services to build". If the gateway
   401s a key that control-api just issued, check the image before the code.
2. **The pepper is a file, so uid alignment is a deployment constraint.** `ingest-gateway` now runs as
   `${VEYRA_UID}:${VEYRA_GID}`; any future service reading `data/keys/*` needs the same. Flagged for
   @B in the changelog, since compose is B's file.
3. **At-least-once, stated rather than solved.** A retry after a 503 that actually succeeded stores
   the same bytes twice under two `event_uid`s. HEC has no idempotency key; the identical `raw_sha256`
   is what lets lineage show they are the same bytes. Documented in `API.md`.
4. **Quota is per gateway instance**, because the bucket is in memory. One instance is what the demo
   runs; a second would double the effective quota. A shared bucket would need Redis or a token
   service, which is out of proportion for the demo — noted so nobody is surprised at CP4.
5. **No per-tenant authorization beyond the key.** A key is bound to one source, so it cannot push as
   another, but there is no scope or expiry beyond `status`. Key rotation works (a re-issue drops the
   old digest, with a test); expiry is C's lifecycle to add if it matters.

## Notes for downstream phases

**A5 (shadow, replay, revisions):** gateway envelopes are ordinary IF-ENVELOPE records on `raw.*`, so
replay treats them like any other — but note `custody` may be `post_hoc` for batch-uploaded events, and
a replay must preserve that rather than stamping `realtime`.

**A6 (router + Wazuh):** nothing new to route; the interesting field for a Wazuh rule is
`ulpf` as before. If a rule wants to distinguish push from syslog, that is `transport` in the envelope
and it reaches the lineage row, not the OCSF event.

**@B:** `hec_meta` is optional and `null` for every syslog envelope, so B1's row builders keep working
untouched; add columns only if the console wants to show "what the shipper claimed". Batch uploads
arrive with `custody=post_hoc`, which the vault and the evidence UI should show differently from
`realtime` — that distinction is the whole reason the flag exists.

**@C:** `services/ingest_gateway/API.md` is the key-card text, already matching `keys.py`'s port and
scheme. Two requests: keep revocation as a republish with `status="revoked"` (A2's AC2 depends on it),
and if key expiry is ever added, express it as a `status` value rather than a timestamp the gateway
would have to interpret — the gateway deliberately has no clock-based policy.
