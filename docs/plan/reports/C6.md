## What was built

**control-api** (TC41):

| Change | Detail |
|---|---|
| `GET /routes` | The IF-ROUTES document (`{routes: [...]}`) for any signed-in user; the Delivery page reads it |
| `POST /onboarding/use-library {source_id, pack}` | Clones a matched library pack into the tenant as the source's version 1 (`provenance.drafted_by: library`) and submits it: 201 with the canary version |
| Re-draft while drafting | `POST /drift/{id}/draft` also accepts a `drafting` item; the new draft supersedes the old one. A superseded draft that finishes late no longer changes the item's state, so the demo's 5 s cache fallback can't be undone by a slow live draft |

**console** (`console/src/`):

| Area | Files | What it does |
|---|---|---|
| API | `api/types.ts`, `queries.ts`, `stream.ts` | C6 types matching control-api's response models; hooks for contracts, drift, drafts, replay, audit, routes; `postStream` (SSE over a POST, TC42) with a shared frame parser |
| Mock world | `mocks/c6.ts`, `mocks/fixtures.ts` | Contracts, drift, drafts, replay, audit, routes and a streamed onboarding analysis, mirroring control-api's rules (role checks, then four-eyes; exact state filters) |

| Review | `components/review/*` | `DraftReview` (compact and full): raw bytes with highlighted spans and the thread, the mapping table with provenance states, inline edits that re-verify, the backtest strip; Submit disabled with the first failure shown (AC4) |
| `/onboard` | `pages/onboard/*` | Source → samples → streamed analysis (layers, message shapes, library match) → compact reviews → Create contract → Approve and activate → key. Progress lives in the URL, so a reload or a demo user switch keeps the step |
| `/contracts`, `/contracts/:id` | `pages/contracts/*` | List; detail with history, a version picker, YAML / Golden / Backtest / Diff tabs, and approve / promote / rollback behind confirm dialogs that say what happens |
| `/drift`, `/drift/:id` | `pages/drift/*` | Inbox cards with state chips and a source filter; the detail page with full review, submit → approve → promote → replay, and replay progress; the 5 s demo cache fallback (TC37) |
| `/delivery`, `/audit` | `pages/delivery/*`, `pages/audit/*` | Routes joined with live statistics and breaker state; the audit log with a text filter and CSV export (RFC 4180) |
| Sources drawer | `pages/sources/SourceDriftList.tsx` | The source's open unknown message shapes with counts, linking to their drift pages (C5's open drawer item) |

## Deviations from the phase file

1. **The four-eyes demo moment.** control-api checks the role before four-eyes, so the author clicking Approve sees *"this action needs one of the roles: admin, pack_approver"*. The four-eyes message appears when an approver approves their own submission. Both are shown verbatim beside the button.
2. **The inbox's "Open" chip** groups open, drafting and draft-ready items: control-api filters on one exact state.
3. **Approve and Promote on the drift page are direct buttons** (Beat 4 pace); the contracts page keeps confirm dialogs for approve, promote and rollback.
4. **Turmeric stays reserved for byte highlights** (C5): new drift cards get the highlight wash and a thread border; the "review" row state is a highlight-token chip.
5. **"Download API guide"** is left out: `GET /sources/{id}/guide` isn't in IF-API-CONTROL.
6. **The Lineage link** after a replay points at B6's `/lineage?q=<sig>`; whether it opens revision 2 depends on B6.
