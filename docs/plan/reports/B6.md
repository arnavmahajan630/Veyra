## What was built

The two pages that carry Beat 5 and point (d): find any event, see its raw bytes beside its
normalized form, hover a field to see exactly which bytes it came from, and verify it
cryptographically.

| Piece | Where | What it does |
|---|---|---|
| `fields.ts` | `console/src/pages/lineage/` | Turns a revision into rows. The client half of P4: each row is either located (`field_offsets`) or declared computed (`derived_fields`), and anything in neither is shown as an unexplained claim. Mirrors `veyra_engine.provenance_check`, including its `_claimed_paths` conventions. |
| `NormalizedPane.tsx` | same | The field list, driven by real offsets. Roving tabindex + `role="listbox"`, so arrow keys and Enter work and focus is visible (AC5). |
| `RevisionDiff.tsx` | same | The rev-1 → rev-2 diff, compared **by value** (A5's convention), green/violet. |
| `VerifyPanel.tsx` | same | The eight-step chain. Reveals only after the response, breaks the thread at the first failure, builds the locating sentence, greys `pending_seal` and `not_implemented`, and owns `Shift+T` / Untamper. |
| `LedgerTable.tsx`, `ChainStrip.tsx` | `console/src/pages/evidence/` | The signed-root ledger, live-appended from the new `root` SSE event, with per-root audit flags colouring the beads. |
| `PublicKeyPanel.tsx` | same | PEM + the SHA-256-of-DER fingerprint. |
| `ExportPanel.tsx` | same | Pick an event by **searching**, download the zip, and see the error when one happens. |
| `lineageFixtures.ts` | `console/src/mocks/` | Mock-mode data whose byte offsets are *computed* with `TextEncoder`, plus a tampered and a pending-seal verify variant. |
| `Revision.field_offsets` / `derived_fields` | `packages/veyra_lineage/models.py` | The read-path fix below. |
| `RawInfo.raw_text` / `raw_b64` | same | The bytes themselves, as IF-API-EVIDENCE always specified. |
| `event: root` | `services/evidence_api/app.py` | Emitted on `/lineage/stream` as each window is signed. |
| `beat5.spec.ts` | `console/e2e/` | Beat 5 end to end in mock mode, plus a keyboard-only pass and the Evidence page. |

## Four things that were wrong, not missing

**1. The signature moment was faked.** `NormalizedPane` highlighted byte spans from hardcoded
literals (`user.name → [44,52]`, `src_endpoint.ip → [66,78]`) and rendered `verified: true`
unconditionally. It looked right for exactly one fixture. The cause was a read-path gap:
`ulpf.field_offsets` is produced by the engine and indexed by `veyra_lineage.rows`, but
`Revision` never exposed it, so `GET /lineage/events/{uid}` could not return it. Offsets are
now lifted onto `Revision` by a validator, which fills every construction site at once, and
each located field is checked against the raw text with the engine's own rule.

**2. The event-detail fallback invented a normalization.** With ClickHouse unreachable, the
vault-scan path returned a fabricated revision — OCSF body, `user.name: a.sharma`,
`src_endpoint.ip: 103.21.4.77`, and a `conformance` value that is not even in the literal.
It now returns `revisions: []` with `index_available: false`, and the page says the index is
unavailable. The console's own hardcoded fallback `rawText` went with it.

**3. `npm run build` was broken.** 26 `tsc` errors, every one in a B6/B7 file, including a
`useSSE` call written as if the hook were generic and keyed by callback name rather than by
SSE event name — which is why the ledger table had never live-appended (AC4). Now 0 errors.

**4. `t(key) || "fallback"` is dead code.** `translate()` returns the key when it is missing,
which is truthy, so every one of those fallbacks was unreachable and the raw key rendered on
screen. 94 keys added to `en.json` and `hi.json` (404 each, in sync).

## Deviations from the phase file

1. **`immudb_verified` renders grey**, and AC2 reads 7 green + 1 grey (above).
2. **Roots live-append via `event: root` on `/lineage/stream`** rather than a second stream,
   so a tab still holds one connection.
3. **The raw pane has no `·` whitespace markers.** Line breaks are preserved and the footer
   carries sha256/length/encoding; the marker idea is cosmetic and was not built.
4. **`/demo` is now gated on `me.demo_mode` at the route**, not only in the nav rail — it was
   reachable by typing the URL on a non-demo machine.

## Known issues / risks

- The live < 2 s verify bound (AC2) and AC3 against a real vault are unmeasured here.
- `ExportPanel` downloads through an anchor, so a browser configured to block programmatic
  downloads will silently do nothing; the error path only covers a failed request.
- The chain strip shows at most 30 beads and does not paginate.

## Notes for downstream phases

- **@C** `EventRevision` now carries `field_offsets` and `derived_fields`, and `RawInfo`
  carries `raw_text`/`raw_b64`. C2's replay panel and C6's drift review can highlight bytes
  the same way the Lineage page does — the helper is `pages/lineage/fields.ts::buildFields`.
- **@C** `api.text()` exists in `api/client.ts` for `text/plain` endpoints. `api.get()` always
  parses JSON, which is what had broken `/pubkey`.
- **@A** The console now trusts `ulpf.field_offsets` completely and will draw a red
  provenance warning on any field whose span does not slice out its value. That is the
  intended behaviour, and it makes an engine regression visible on screen immediately.
