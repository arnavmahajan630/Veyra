## What was built

**`packages/veyra_common`** — the foundation every service imports:
- `settings.Settings`: every knob in `03_INFRA_PROFILES.md` §2 with laptop defaults (P5). A test
  rejects any profile key that is not a declared knob, so a typo fails CI instead of doing nothing.
- `models/`: Pydantic v2 for IF-ENVELOPE, IF-ULPF, IF-NORM-EVENT, IF-LINEAGE, IF-DLQ, IF-SHADOW,
  IF-VAULT-INDEX (discriminated event/segment union), IF-RECEIPT, IF-AUDIT, IF-SIGNED-ROOT and every
  IF-CONTROL value. Closed records (`extra="forbid"`) so a consumer notices an unexpected producer
  field; the OCSF body stays open on purpose.
- `hashing`: the frozen IF-TEMPLATE-SIG reference. Tests assert all three contract vectors **and**
  run `docs/plan/reference/spec_vectors.py` itself and compare, so drift is impossible.
- `envelope.stamp` + `framing.split_lines`: one stamping and framing rule for the edge (A1) and the
  gateway (A2). `fixtures/envelope_vectors.json` holds the three parity vectors A1 task 8 needs.
- `topics`: IF-TOPICS specs and an idempotent `create_topics()` behind `make topics`.
- `kafka`: durable producer/consumer plus `TxnProcessor` — outputs and consumed offsets commit in
  one transaction, with an abort-and-retry path and a poison-batch guard.
- `service.ServiceApp`: JSON logs, `/healthz` + `/metrics`, readiness gate, graceful stop.

**`packages/veyra_engine`** — the S0 stub: frozen IF-ENGINE-LIB surface, tier-4 output with a complete
valid IF-ULPF, real `template_sig` and a real simple `extract_tokens`. Its tests pin the *surface and
the invariants* (purity, tier ∈ 1..4, every token span slices back to its value), not the stub's
answer, so they keep passing when A3 replaces the internals.

**Infrastructure**: Kafka (KRaft, single node), ClickHouse 25.8, immudb 1.11.2 (pg wire), two Vector
edges with placeholder configs publishing to `raw.unregistered`, Caddy on one origin, and Wazuh 4.14.8
single-node in its own compose file so `WAZUH=remote` can skip it. One Python image, reused by every
service with a different command, gated behind per-phase compose profiles.

**Corpus**: 6 files, reproducible from `demo/tools/gen_corpus.py` — sshd (with a 6-failure brute-force
burst for rule 100111), CEF allow/deny/threat, the three authsrv templates verbatim from
`04_DEMO_SCRIPT.md` §2.1 (T3 with its stack-trace continuation, exactly 8 events), an OT historian with
Devanagari tag fields (A4 AC2), and `garbage.bin` (invalid UTF-8, NUL run, 1-byte line, empty line,
200 KB line, truncated JSON, cut CEF header).

## Deviations from the phase file

1. **Node 25, not 20/22 LTS** (D17) — the host toolchain, and per D2 there is no Node at runtime.
2. **`compose/wazuh/indexer.yml` does not exist.** The 4.14 indexer image generates its own
   `config/opensearch.yml` from the environment; a mounted custom file is silently ignored. Certificates
   go to `config/certs/` with the names that generated config expects.
3. **`make wazuh-init` is a new step** the phase file did not anticipate: the security index must be
   initialised with our CA once after `make wazuh-certs`, or the indexer answers "OpenSearch Security
   not initialized" and the dashboard serves 503.
4. **Wazuh credentials are the image defaults** (admin/admin, kibanaserver) because `securityadmin`
   uploads the image's own `internal_users.yml`. The knobs now say so. Rotation is an S2 item.
5. **Byte-size knobs are integers** (`VEYRA_SEGMENT_MAX_BYTES=2097152`) rather than `2MB` strings, so
   they are typed in `Settings` and need no parser.
6. **`contracts-repo` history is created at runtime** (`make contracts-repo-init`). The seed YAML is
   tracked in the outer repo; an embedded `.git` would have made it a gitlink invisible to a fresh clone.
7. **Python services are behind compose profiles** (`SERVICES="a2 a3 a6"`), so `make up` on a fresh
   clone starts only what actually works.

## Known issues / risks

1. **The LLM runs on CPU, not GPU — S0.5's "100% GPU" check FAILS.** `ollama ps` reports `100% CPU`;
   Ollama's GPU discovery finds only `library=cpu` even though the driver (580.178.04), `/dev/nvidia*`,
   `libcuda.so.1` and Ollama's bundled `cuda_v12` runner are all present. Measured draft latency on CPU:
   **53–91 s** per request, against a demo fallback window of 5 s. **Consequence:** the Beat 2/Beat 4
   drafts must come from `LLM_MODE=cache` until this is fixed. `ACTION REQUIRED @C` in the changelog.
2. **Ollama now listens on `0.0.0.0:11434`** (systemd drop-in `/etc/systemd/system/ollama.service.d/veyra-host.conf`),
   which is what makes AC5 work. It exposes the LLM API on the LAN while Wi-Fi is on; the demo runs
   air-gapped with Wi-Fi off (`04_DEMO_SCRIPT.md` §5).
3. **Host port collisions on this machine.** Another project holds 8080, and a local PostgreSQL holds
   5432; `.env.local` maps the console to 8081. Both are knobs now, so the demo laptop can still use
   the documented 8080.
4. **The laptop power-cut once during this phase** under image builds + Wazuh + tests (GPU fan spun up,
   chassis vibration, then poweroff). Idle draw afterwards is calm (62 °C, 9 % GPU). Before the demo:
   no builds, no `make test-int`, and watch thermals during rehearsal (S2 item 2 covers failure injection).
5. **`wazuh-analysisd` logs `Could not set resource limit for file descriptors`** — harmless in a
   container without `CAP_SYS_RESOURCE`, but it appears in every manager start.
6. **Filebeat's registry is fragile if you kill filebeat by hand.** Killing it mid-session left the
   supervised instance not shipping; recreating the container plus removing the `veyra_filebeat_var`
   volume fixed it. Do not `pkill filebeat` inside the manager — restart the container.
7. **`make wipe-data` needs `sudo`** because the Wazuh certificate generator writes root-owned files.
