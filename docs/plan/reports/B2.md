## What was built

| Piece | Where | What it does |
|---|---|---|
| Segment format | `packages/veyra_evidence/segment.py` | `SegmentWriter` / `SegmentReader`: append-only records, a header carrying the chain head, AES-256-GCM per segment, sealed at `SEGMENT_MAX_BYTES` or `SEGMENT_MAX_SECONDS` |
| Hash chain | `veyra_evidence/chain.py` | `genesis`/`step`/fold over `(raw_sha256, event_uid, offset)` per partition; a reader recomputes a segment's chain and compares it with the header |
| Digest | `veyra_evidence/digest.py` | `segment_digest_hex`, the Merkle leaf B3 signs |
| Keys | `veyra_evidence/keys.py` | `KeyProvider` (IF-KEYPROVIDER) with the local file provider, Ed25519 signing and `verify_signature` |
| Archiver service | `services/archiver/` | Consumes `raw.*`, writes segments, publishes `IF-VAULT-INDEX` (one segment record plus one per event, at each seal, before the offset commit), sets sealed segments to mode `0444`. `chattr +i` is **not** applied — the mode is a guard against an accident, and the signed Merkle root is what catches a deliberate edit |

## How to run and test
