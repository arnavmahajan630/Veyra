- **Date / author (human + agent):** 2026-09-29, Person A (Arnav) with Claude Opus 5

## What was built

A5 closes the contract loop. A candidate version can now run beside the active one on live traffic
without touching a single delivered event, the control plane gets an instant before/after for the
version it is about to approve, and replayed history supersedes itself instead of piling up.

| Piece | Where | What it does |
|---|---|---|
| `Engine.shadow(envelope, active)` | `veyra_engine/engine.py` | Runs the candidate under its **own** budget and returns a `ShadowDiff`. `None` when the source has no candidate, which is the common case and costs nothing. |
| `_compare_events` | same | `(changed_fields, regressions)` by **value**, built on A4's `_claimed_paths` so "a claim" and "a change" mean the same thing in both phases. |
| `ShadowDiff` / `shadow_budget_us` | `veyra_engine/types.py` | The diff, and the canary's separate budget. |
| `_shadow_record` | `services/normalizer/` | Emits the `IF-SHADOW` record **in the same transaction** as the event it describes. |
| `_parse` | `services/normalizer/` | Validates `ReplayEnvelope` when the value carries a `replay` block — the fix for the bug below. |
| `backtest(..., budget_us=)` | `veyra_engine/engine.py` | Adds `field_coverage`, value-based `changed_fields`, and a budget that suits stored events. |
| `tools/mock_replay.py` | A-owned scaffolding | Publishes `replay.raw` from real `raw.*` envelopes, so replay is testable before B4's evidence-api exists. |

## Three bugs this phase found

**1. `replay.raw` had never worked.** `Envelope` is `extra="forbid"`, and a replayed record carries an
extra `replay` block — so **every replay message was rejected as a broken envelope and DLQ'd as
`schema_invalid`**. A3's note said the plumbing was already in place; it was, apart from the one line
that decides whether the message parses at all. C2's replay jobs would have timed out at CP3 with a
reason pointing at the wrong track. `normalizer._parse` now validates `ReplayEnvelope` when the value
has a `replay` key, and a malformed block degrades to an ordinary event rather than dropping it (P2).

**2. `Budget.expired()` read a limit of 0 as "already over".** A backtest asking for "no limit" turned
every event into `budget_exceeded`. Found immediately by the backtest budget test, and it would have
been found the hard way by the first bulk backtest C2 ran.

**3. A4's crash-loop journal was silently inert in the real stack.** `veyra-normalizer` runs as uid
10001 while `data/state/` belongs to the invoking user, so every journal write failed with
`Permission denied` — and because the journal is deliberately non-fatal, nothing looked wrong. The
container now runs as `${VEYRA_UID}:${VEYRA_GID}` like `control-api` and `ingest-gateway`. This is the
second time this exact shape has bitten (A2's pepper file was the first), which is why it is in the
changelog as a rule rather than a fix.

## Design decisions worth recording

1. **`changed_fields` compares values, not offsets.** The placeholder diffed `field_offsets` keys,
   which reports a field that merely stopped being located — not a change to any datum a SIEM rule
   reads. What an approver needs is the opposite: the paths whose **values** appear or differ, and
   `regressions` for paths the active version claimed and the candidate no longer does.
2. **A tier that got worse is itself a regression**, recorded as `tier:1->3`, because a candidate can
   lose everything without losing a single named path.
3. **The shadow has its own budget** (`VEYRA_SHADOW_BUDGET_US`). A canary is under review; it must not
   be able to delay the event an operator is waiting for. Over budget → the comparison is skipped and
   counted; the event is untouched.
4. **The shadow record shares the event's transaction.** A shadow row that survived a crash the event
   did not would describe a comparison that never happened.
5. **The replay revision is used exactly as sent.** control-api computes `latest + 1` from the lineage
   index; the normalizer never recomputes it. That is what makes a record re-processed after a crash
   produce the same `(event_uid, revision)` and lets B1's ReplacingMergeTree collapse it.
6. **`backtest()` kept its shape for C.** C2 and C4 call it positionally and `asdict()` the result, and
   the console's `BacktestExample` is built against the example keys, so `field_coverage` is purely
   additive.

## Deviations from the phase file

1. **AC2 says "8 T3 envelopes"; the corpus holds 14.** `gen_corpus.py` grew the T3 file after the
   phase file was written. The test asserts all 14 upgrade with zero regressions — the same claim,
   stricter.
2. **`Engine.shadow` is a separate call, not a flag on `normalize`.** Keeping `normalize` single-purpose
   is what lets the caller decide when a shadow is worth running, and it keeps the pure function that
   A3's determinism tests pin unchanged.
3. **Integration tests publish `control` messages directly** rather than driving control-api's HTTP
   lifecycle, so A's tests do not depend on C's endpoints being up. The message shape is C's
   (`ContractMessage`).

## Known issues / risks

1. **Shadow doubles the engine work for sources with a candidate.** That is inherent, and it is why
   the budget is separate — but at CP4 scale, a canary on a high-EPS source is the one thing that
   could move the throughput bench. A6 should bench with a canary attached, not only without.
2. **The shadow record carries no event text**, by design (it is a comparison, not a copy). Anything
   joining it to an event — the console, a test — must join on `event_uid`. Both A5 integration tests
   tripped over this while being written; it is worth knowing before B6 builds the drift view.
3. **`tools/mock_replay.py` reads `raw.*` from the beginning**, which is fine for a demo-sized topic
   and wrong for a real one. It is scaffolding until C2's job can resolve events through B4. Its
   `--contains` flag was a finding rather than a nicety: the first AC3 run replayed the *oldest* eight
   events on the source — every earlier run's leftovers — instead of the ones the test had just sent,
   and passed the tool's own checks while proving nothing. `--contains` matches the **decoded** raw
   bytes, because they travel base64-encoded, which is also why "replay this user's events" cannot be
   a grep over the topic.
4. **A replay uses whatever is active at replay time**, as the phase file specifies. That means
   replaying before promoting produces the *old* result — correct, and surprising if someone replays
   first out of habit. Worth a line in the demo script's Beat 4 ordering.

## Notes for downstream phases

**A6 (router + Wazuh + bench):** `shadow` is a new topic with real traffic — it is not routed anywhere
and should not be. For the throughput bench, run one pass with a candidate attached to a busy source:
that is the realistic worst case now, and `veyra_shadow_skipped_total` tells you whether the canary was
actually keeping up.

**@B:** `shadow_diffs` receives real rows for the first time — worth a look at CP2, since that code
path had never seen a message. And the compose `user:` rule now applies to three services; anything of
yours that writes under `data/` needs it too.

**@C:** `field_coverage` is in the backtest response already (additive). Replay progress works end to
end: `lineage.replay_job_id` and `revision` come from the block exactly as sent, so `ReplayWatcher`
counts what it expects. One behaviour to know: a replay message with a malformed block is delivered as
an ordinary event rather than dropped, so such a job reports `timed_out` rather than `failed`.
